# Rust 1.99 CI compatibility verification

Date: 2026-10-02
Branch: `refactor/furnance-injector`
Baseline: `18fe1d7`
Status: Implemented and verified locally; no push or CI rerun performed.

## Reproduced failures

The reported coverage run failed four of 35 compile-fail fixtures. The same failure was reproduced with Rust 1.99.0: controller_dependency, injector_non_clone_dependency, injector_too_many_dependencies, and managed_dependency. Rust 1.99 summarizes tuple trait implementations as `(T₁, T₂, …, Tₙ) up to tuples of arity 16`; earlier compiler snapshots enumerate implementations. Rejection behavior and error codes are unchanged.

The official stable manifest published Rust 1.99.0 on 2026-10-01. CI tracks stable, while previous local verification used Rust 1.96.0. Preliminary Rust 1.96/1.98 coverage and UI runs passed; these older runs did not reproduce the new diagnostics. Full CI logs required authentication; diagnosis uses the exact locally reproduced four failures, not an assumed interpretation of the summary.

Strict Clippy on Rust 1.99 also rejected redundant generated field initializers and the newly deprecated Atomic::fetch_update in a test helper. A Rust 1.94 probe confirmed that Atomic::try_update is still unstable there.

## Fix

- Keep exact compile-fail snapshots for both pre-1.99 and 1.99+ tuple diagnostics, selected from the active rustc major/minor version. Existing MSRV/stable snapshots for other diagnostics remain selected separately. All 35 negative fixtures still run; none are skipped or weakened.
- Generate shorthand field initializers in both managed provider and controller constructors.
- Allow the fetch_update deprecation only on the existing authorization test helper, preserving the Rust 1.94 MSRV without suppressing workspace linting.
