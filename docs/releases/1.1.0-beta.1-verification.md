# 1.1.0-beta.1 verification

Verified on the isolated `refactor/compile-time-di-checker` branch against base `8c08bba`. The beta is prepared locally; it has not been published, tagged, pushed or merged. MSRV remains Rust 1.94; stable checks use Rust 1.96.

## TDD history

Each implementation commit contains its tests and working implementation. RED results were observed before changing production code; intentionally broken commits were not manufactured.

| Change | Observed RED | GREEN / commit |
| --- | --- | --- |
| Declarative registration | New attribute arguments rejected | Runtime registration parity and parser UI tests; `2cfca1e` |
| Root contract | Missing dependency fixture unexpectedly compiled with an empty main | Scope, globals, aliases, private types, native bindings and collision controls; `9dc47ed` |
| Injection marker | Managed fields rejected the new attribute | Mixed-field identity, lifecycle, controller and invalid-marker tests; `f38d019` |
| Infrastructure metadata | Valid root could not import database/logger contracts | Cross-crate contracts, native mock connection, custom/default logger and diamond lifecycle; `30d585d` |
| Intrinsic Config overlap | Valid explicit Config/alias provider failed with E0283 | Rust type identity removes redundant membership while missing factory inputs still fail; `0260891` |
| Runnable example | Compile-fail harness rejected an unexpectedly valid logger import | Removing that import produces the intended missing Logger error on stable and MSRV |

The initial global-witness inference prototype failed valid overlap graphs. The revised metadata mechanism passed 30 expected-outcome checks on each toolchain plus declaration collision controls before product implementation. The design records this gate and the resulting beta import restriction.

## Review

An independent branch review found an explicit Config/intrinsic membership ambiguity. A regression reproduced it before the fix. The reviewer then confirmed alias handling, missing constructor checks and `deny(warnings)` behavior, with no further actionable finding in the fix. Legacy fluent API and runtime graph analysis remain available. Declarative imports accept qualified paths, re-exports and use aliases; module type aliases remain a documented beta limitation.

## Migration of the remaining examples

The four existing examples now use declarative cauldron registrations and marked application roots. Managed dependency fields use optional `#[inject]` markers. The protected-route module explicitly provides `JwtService` using its existing Config-based injector, so the static graph no longer relies on an implicit runtime auto-configuration output. Trait bindings retain their existing constructors using `Output => Injector`. Routes, configuration and entry points remain the same.

Before migration, temporary copies of posts-crud without its DatabaseCauldron import and protected-route without its LoggerCauldron import still compiled. After migration, removing DatabaseCauldron from either CRUD root, LoggerCauldron from the auth root, or JwtService from AuthCauldron fails with E0277 for the corresponding dependency lookup. The negative probes use temporary copies, leaving the runnable projects valid.

For each of `hello-world`, `posts-crud`, `post-crud-with-service` and `protected-route`, these checks passed:


HTTP smoke tests on ephemeral localhost ports verified Hello World's response, unauthenticated profile rejection, incorrect-password rejection, successful login, JWT-authenticated profile access and graceful SIGTERM shutdown. They used copies of the shipped example configuration and demo environment template. The CRUD examples compiled and ran their ordinary unit suites; no external PostgreSQL execution is claimed for this migration. No engine change was required.

## Standalone missing-dependency example

`example/missing-dependency` deliberately registers OrderService without its
required OrderRepository. Its empty main proves that the marked root is checked
without startup. `cargo check --offline --locked --manifest-path
example/missing-dependency/Cargo.toml` fails with E0277 for
`Lookup<OrderRepository, _>` on stable and Rust 1.94. `cargo test` also fails
before execution. Temporary copies with OrderRepository added to the provider
list compile on both toolchains. Formatting and whitespace checks passed. The
intentional failure is isolated in its own workspace, and its README documents
the failure command and repair.
