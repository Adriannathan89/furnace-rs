## Package and toolchain contract

All nine workspace packages target `1.0.0`; internal package dependencies use
exact `=1.0.0` pins so their public Rust types share one framework version.
The workspace uses Rust edition 2024 and MSRV 1.94. The optional PostgreSQL
connector uses SeaORM 2.0, with a minimum-version gate for SeaORM 2.0.0.
Persistence is selected explicitly through `furnace-rs-persistence` and its
`sea-orm-postgres` feature. SeaORM owns native queries, transactions and migrations.

The stable and beta publication workflows currently use this dependency order:

1. `furnace-rs-core-macros`
2. `furnace-rs-common-macros`
3. `furnace-rs-core`
4. `furnace-rs-extra`
5. `furnace-rs-common`
6. `furnace-rs-testing`
7. `furnace-rs`
8. `furnace-rs-persistence`
9. `furnace-rs-cli`

The renamed package family must be available on the registry before registry-only
installation or scaffold builds against `=1.0.0` can succeed. Local preparation
uses workspace/path dependencies and does not prove registry availability.

## Breaking migration

This major release changes the MADS declaration and package surface. There are
no compatibility aliases for the removed declarations. Follow the
[migration guide](../importance/furnace-rs-migration.md) for complete examples.

- Rename `mads`/`mads-*` packages and imports to `furnace-rs`/`furnace-rs-*`;
  use the `furnace` executable, `furnace.toml` and `FURNACE_*` configuration.
- Replace module/service/repository declarations with `#[cauldron]`,
  `#[burner]` and `#[storage]`. Select native and trait-object outputs through
  explicit `Injector<T>` implementations and `.provide_with::<T, I>()`.
  Replace provider/element constructors and lifecycle forms with
  `Injector::inject` and `Injector::lifecycle`.
- Declare controllers on a struct and exactly one annotated inherent
  implementation. Replace route traits and trait/method guards with static
  unit-struct guard policies and controller seals. `#[seal(skip)]` makes an
  individual endpoint public; an omitted seal also leaves a controller public.
- Replace `Mads::run`/`MadsRunExt` with `Furnace::burn`/`FurnaceBurnExt`.
- Update machine-output consumers to public CLI schema 2 and private inspection
  protocol 2. Route records no longer contain the removed route-trait field;
  graph records use `root_cauldron` and `cauldrons`.

## Security changes included in preparation

The prior reviews confirmed and patched these issues; their reports distinguish
reproduced behavior, trust assumptions and verification limits:

- Bearer credentials now require the RFC 6750 internal ASCII-space grammar and
  token alphabet. Invalid forms reject before strategy/handler invocation.
  See [Bearer parsing hardening](../../benchmark/SECURITY.md).
- Core error `Debug` formatting omits retained causes, database timeouts use
  checked deadline validation, and connector-owned tracing suppresses native
  connection spans that could expose credentials. See
  [core and connector review](../../benchmark/INFRASTRUCTURE_SECURITY.md).
- Unix CLI inspection and development control directories request `0700` at
  creation instead of inheriting permissive umasks. See the
  [all-crate review](../../benchmark/ALL_CRATES_SECURITY_AUDIT.md).

The all-crate report also records dependency advisory scans and their database
snapshot. These historical results are preserved alongside a refreshed local advisory scan.
Registry availability and remote release checks remain separate gates. The reviews do not claim exhaustive
vulnerability absence, and their Windows runtime limits still apply.

## Reproducing local checks

Use Python 3.11 or newer and the documented Rust toolchains. Keep temporary
build artifacts outside the checkout:

```sh
export CARGO_TARGET_DIR="$(mktemp -d /tmp/furnace-v100-build.XXXXXX)"
cargo fmt --all --check
cargo clippy --locked --workspace --all-targets --all-features -- -D warnings
cargo test --locked --workspace --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --locked --workspace --all-features --no-deps
cargo +1.94.0 test --locked --workspace --all-features
cargo package --locked --workspace --no-verify --allow-dirty
cargo audit --no-yanked --file Cargo.lock
python3 benchmark/tool/infrastructure_security.py --profile smoke
python3 benchmark/tool/cli_security.py --profile smoke
```

The package command permits this prepared working tree; the publication workflow
runs from a clean checkout. Offline security runners require cached dependencies
(`cargo fetch --locked` populates them).

For live integration, provision a disposable PostgreSQL 16 database and export
`FURNACE_TEST_DATABASE_URL` with its connection URL. Then run:

```sh
cargo test --locked -p furnace-rs-persistence --features sea-orm-postgres \
  --test postgres -- --ignored --test-threads=1
```

For the release coverage gate, install `cargo-llvm-cov` and the toolchain's
`llvm-tools-preview` component, retain the database URL, and run the CI command:

```sh
cargo llvm-cov --workspace --all-features \
  --ignore-filename-regex '(^|/)tests/ui/' --fail-under-lines 85
```
