# 2.0.0-beta.3 verification

Review date: 2026-10-16. Starting checkout: `f6bd3cf` on `develop`.

## Review scope

The review covered entity storage CRUD and query forwarding, pagination bounds,
relation macro generation, storage error conversion, database providers and
lifecycle wiring, and the release scripts, workflows, manifests, and lockfiles.
It also inspected the existing lifecycle/configuration, HTTP timeout, and gRPC
policy/deadline corrections listed in the [beta.3 release notes](2.0.0-beta.3.md)
and the [benchmark security report](../../benchmark/SECURITY.md#f01-conditional-grpc-admission-policy).
This is a source review with regression checks, not a guarantee that every
possible defect has been discovered.

No additional runtime vulnerability was confirmed during this review. Existing
runtime fixes from the preceding beta review remain documented separately.

## Environment and limits

Local verification uses Linux, Rust 1.99.0, and PostgreSQL 16. Rust 1.94.0 is
checked separately as the declared minimum compiler. Database acceptance uses
an isolated temporary PostgreSQL instance bound to loopback; no application
database is migrated or modified.

The advisory check uses cached RustSec database commit `caee11f4`, dated
2026-10-14. All 12 committed lockfiles report zero known vulnerabilities against
that snapshot. A separate scan of cached crates.io registry metadata finds zero
yanked entries and no missing metadata across 419 unique registry versions.
`cargo audit --no-yanked` skips yanked checks, so the separate scan is necessary.

Network and loopback restrictions prevented the initial sandboxed socket tests
from running; those checks are rerun with loopback access. macOS/Windows,
coverage enforcement, and the fresh online advisory check are delegated to
repository CI before publication.
