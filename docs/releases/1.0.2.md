# furnace-rs 1.0.2 — Released

Version **1.0.2 is released** on
[crates.io](https://crates.io/crates/furnace-rs/1.0.2). All nine workspace packages target `1.0.2` with exact `=1.0.2` internal dependency pins. The four
independent examples use the same framework version. Edition 2024, Rust 1.94,
and the SeaORM 2.0.0 minimum remain unchanged.

Install the released CLI with:

```sh
cargo install furnace-rs-cli --version 1.0.2 --locked
```

## Changes

- Enable the opt-in `sea-orm` feature on the facade or HTTP crate to propagate
  native query `DbErr` values with `?` in `HttpResult` handlers. Failures return
  redacted JSON 500 responses and retain the original error source for diagnosis.
  The feature enables HTTP but selects no database driver or connection provider.
- Make `example/posts-crud` call its repository directly. Use the independent
  `example/post-crud-with-service` project when a service layer is useful.
  Both projects include PostgreSQL setup instructions and validated input.
- Enable aligned debug request logs with `[furnace] mode = "debug"`, including
  timestamps, final status, method, and path without query strings.
- List every registered route in the startup summary, with uppercase methods
  and full controller-prefixed paths.
- Redact custom Serde missing-field error text from validated-extractor issue
  paths while preserving HTTP 422 and structured containing paths. See the
  [security writeup and evidence](../security/2026-10-09-extractor-error-redaction.md).
- Stabilize CLI development-process and missing-registration diagnostic tests.

`Path<T>` remains the native Axum extractor. Use `ValidatedPath<T>` when its
validated JSON rejection contract is needed. Connector `PersistenceError`
values remain separate from native query `DbErr` values.

## Verification

Local preparation checks passed on 2026-10-09: full workspace and documentation
tests on Rust 1.96.0 and the Rust 1.94.0 MSRV, clippy with warnings denied,
formatting, locked builds of all four examples, minimal `sea-orm` feature
checks, version/lockfile alignment, and the package-content policy for all nine
crates. Live PostgreSQL tests remained ignored in these local runs.

Reproduce the local verification gates from the repository root:

```sh
cargo fmt --all --check
cargo clippy --offline --locked --workspace --all-targets --all-features -- -D warnings
cargo test --offline --locked --workspace --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --offline --locked --workspace --all-features --no-deps
bash script/verify-package-contents.sh
```

Build each of the four independent examples with `cargo check --locked
--all-targets --manifest-path example/<project>/Cargo.toml`.

CI additionally verifies Rust 1.94, dependency advisories, security regressions,
SeaORM 2.0.0, live PostgreSQL 16, CLI behavior on Linux/macOS/Windows, crate
archives, and 85% line coverage. Live PostgreSQL tests require a disposable
database and `FURNACE_TEST_DATABASE_URL`:

```sh
cargo test --locked -p furnace-rs-persistence --all-features \
  --test postgres --test recovery -- --ignored --test-threads=1
```

For subsequent stable releases, the stable workflow runs those gates, publishes
missing versions of all nine crates in dependency order, and creates the version
tag and GitHub release using the corresponding changelog section.
