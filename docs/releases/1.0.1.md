# furnace-rs 1.0.1 — Release preparation for 2026-10-06

All nine workspace packages target `1.0.1` with exact `=1.0.1` internal
dependency pins. Local examples use the same version. Edition 2024 and Rust
1.94 remain the toolchain contract.

## Changes

- Bound incomplete initial HTTP requests and HTTP/1 headers to ten seconds.
- Add a ten-second idle deadline for pending request-body reads. Progress renews
  the deadline; stalled reads return HTTP 408 before response headers are sent.
- Reject zero database idle/lifetime maintenance durations before pool creation.
  Native `None` values still disable those maintenance policies.
- Reject inventory outputs with a mismatched concrete type before application
  construction succeeds, returning `FURNACE004`.

See the [1.0.1 changelog](../../CHANGELOG.md) for behavior and compatibility
details. Applications using zero database maintenance durations must select a
positive duration or disable the policy through native options with `None`.

The [HTTP benchmark](../../benchmark/HTTP_RUNTIME_SECURITY.md) and
[database, JWT, and inventory benchmark](../../benchmark/DATABASE_INVENTORY_SECURITY.md)
retain before/after evidence for their recorded source revisions. JWT algorithm
binding and PostgreSQL recovery passed before and after the latest patches.

## Release gates

Local preparation validation passed on 2026-10-06: 785 workspace tests passed
with 7 live PostgreSQL tests ignored, all 22 release-automation tests passed,
and all three examples built with locked dependencies. Clippy with warnings
denied, formatting, and version/lockfile alignment checks also passed.
Live PostgreSQL execution and remote publication gates remain separate checks.

Preparation does not establish registry publication. Before publishing, run
the repository's CI and stable publication gates, including:

```sh
cargo test --offline --locked --workspace --all-features
cargo clippy --offline --locked --workspace --all-targets --all-features -- -D warnings
cargo fmt --all -- --check
bash script/verify-package-contents.sh
```

For live PostgreSQL checks, use a disposable PostgreSQL 16 instance and set
`FURNACE_TEST_DATABASE_URL` to its URL:

```sh
cargo test --locked -p furnace-rs-persistence --all-features \
  --test postgres --test recovery -- --ignored --test-threads=1
```

The stable workflow publishes all nine packages in dependency order when the
prepared release reaches `main`, then creates its version tag and GitHub release.
This branch preparation performs only local metadata and documentation changes.
