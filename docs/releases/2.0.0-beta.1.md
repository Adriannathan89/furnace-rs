# 2.0.0-beta.1 release preparation

FURNACE 2.0 makes dependency injection explicit and includes declarative registration with compile-time checking of a selected root. The workspace, internal dependency pins and local examples target `2.0.0-beta.1`. Publication happens through the beta publish workflow after integration into `main`; this branch prepares the release and does not itself publish packages.

## Migration from 1.x

Add parameterless `#[inject]` to every dependency field on structs annotated with `#[burner]`, `#[storage]` or `#[controller]`:

```rust
#[burner]
struct Service {
    #[inject]
    repository: Repository,
}
```

All named fields on these managed structs are dependencies. An unmarked field now fails compilation instead of being injected implicitly. There is no ordinary stored-state field mode or optional injection. Unit structs require no marker, and manual `Injector` implementations continue to declare their typed dependencies using `Injector::Dependencies`.

Declare registrations through `#[cauldron(providers = [...], controllers = [...], imports = [...], exports = [...], global)]`. Add `root` to the application's selected root to check dependency availability and module visibility at compile time. Bare cauldrons and fluent registrations remain supported and retain runtime validation. DatabaseCauldron and LoggerCauldron participate in the declarative contract. See the [DI guide](../declarative-di.md) and [executable example](../../example/compile-time-di/).

## Checker guarantees and limits

The checker validates local providers, direct exported imports, reachable exported globals and intrinsic Config against every declared constructor dependency. It checks imported module constructors as well as the selected root. It does not guarantee that async construction, configuration, database connections, lifecycle callbacks or HTTP binding succeed. Duplicate output ownership and provider cycles still use runtime preflight validation.

Declarative module imports support qualified paths, re-exports and `use ... as ...`; module `type` aliases remain unsupported. Large graphs remain subject to compiler expansion limits. Dependency/output type aliases continue to work.

Review found and reproduced checkout-dependent callback names in compile-fail diagnostics. The fix derives callback names from the relative source location while retaining module and slot identity UIDs for checker deduplication.

Recorded test commands, review findings and remaining validation limits are in [the verification record](2.0.0-beta.1-verification.md). Historical beta benchmarks describe the code they measured; they are not measurements of this mandatory-marker release.
